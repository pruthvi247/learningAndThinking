# Mapping DPI Results to Security Frameworks

## Mapping DPI Results to Security Frameworks

Mapping Deep Packet Inspection (DPI) results to security frameworks is an essential practice for translating complex network data into actionable cybersecurity insights. This process helps organizations align their DPI outputs with standardized security controls, enabling improved threat detection, compliance reporting, and risk management. It transforms raw DPI alerts into structured intelligence that supports strategic security decisions.

This reading explores the steps to align DPI outputs with specific controls in frameworks such as NIST CSF, ISO 27001, or MITRE ATT&CK. You will also learn how DPI findings support compliance with regulatory and industry security standards and how to develop a mapping matrix that links DPI-generated alerts to corresponding security framework elements.

## Introduction

Mapping DPI results into security frameworks connects the specific findings and detections from your DPI system to the established guidelines, best practices, and controls in a recognized cybersecurity framework.

A security framework is like a blueprint or a structured checklist for building and supporting a strong cybersecurity posture. It outlines various categories of security activities, risks, and controls an organization should have. Your DPI system is a powerful monitoring tool, constantly analyzing your network's traffic. Mapping means taking the alerts and insights generated by your DPI and systematically linking them to specific items on that security blueprint. It's about translating highly technical network observations into a common, structured language that helps an organization understand how its security efforts, particularly those from DPI, contribute to meeting defined security objectives and mitigating risks.

### Why is it important?

Mapping DPI results to security frameworks is critical for several reasons:

- Without mapping, DPI data can be a flood of technical alerts that are hard to prioritize. Frameworks provide a common language and a systematic approach to managing security risks.
- Many organizations must follow various regulations (that is, GDPR, HIPAA, PCI DSS) or industry standards. These regulations often mandate specific security controls.
- DPI can find specific threats (that is, command-and-control traffic, data exfiltration attempts, and unapproved applications).
- Security frameworks provide a standardized way to talk about security.
- Frameworks specifically detail adversary tactics and techniques.

### How to map DPI results to security frameworks

Mapping DPI results to security frameworks involves a structured process:

1. **Choose your framework:**
    - Select the security framework(s) most relevant to your organization's industry, regulatory requirements, and risk posture. Common choices include:
        - NIST Cybersecurity Framework (CSF)
        - ISO 27001
        - MITRE ATT&CK
2. **Understand your DPI capabilities and outputs:**
    - Familiarize yourself with what your specific DPI system can detect. What types of alerts does it generate? What information is included in those alerts (that is, application found, threat signature, policy violation type, IP addresses, ports, timestamps)?
    - Know the difference between signature-based detections (that is, "known malware detected") and behavioral anomalies (i.e., "unusual data exfiltration attempt").
3. **Map DPI findings to framework controls/categories:**
    - For NIST CSF or ISO 27001: Go through each control or sub-category in the framework. Ask yourself: "Can my DPI system provide evidence or directly contribute to fulfilling this control?"
    - For MITRE ATT&CK: This framework maps directly to adversary tactics and techniques. When your DPI system generates an alert, link it to a specific MITRE ATT&CK technique.
4. **Document the mapping:**
    - Create a matrix or a written report that links your DPI capabilities and specific alert types to the relevant framework elements.
    - For each framework control or technique, document how DPI helps fulfill it, and what specific DPI alerts or features are involved. This documentation is vital for audits and for communicating your security posture.
5. **Integrate and automate where possible:**
    - Ideally, your Security Information and Event Management (SIEM) system or other security orchestration tools can ingest DPI alerts and automatically tag them with the corresponding framework categories.
    - This automation helps generate reports that show compliance progress or specific threat coverage based on the framework.

## Summary

In this reading, you learned that:

- Deep packet inspection enhances visibility by allowing organizations to analyze the full content of network packets, revealing threats, anomalies, and application usage.
- Security frameworks like NIST CSF, ISO 27001, and MITRE ATT&CK provide structured guidance and a common language for managing cybersecurity.
- Mapping DPI results to security frameworks adds value by translating technical alerts into actionable insights that support compliance and risk management.
- Clear documentation of DPI-to-framework mappings improves audit readiness and helps communicate the organization’s security posture effectively.
- Automating the mapping process through SIEM or orchestration tools supports scalability and enables real-time alignment with security objectives.

### Uses of DPI in ethical hacking

Here's how DPI can be used in ethical hacking:

- **Understand target network policies**: Ethical hackers can infer security policies by seeing how a network's DPI system reacts, which helps in understanding what types of traffic are allowed or restricted, guiding later testing efforts.
- **Identify application and protocol usage**: DPI's ability to classify applications regardless of port helps ethical hackers understand the legitimate services running on a network. This reconnaissance can reveal potential targets or typical traffic patterns to blend into.
- **Gauge defensive capabilities or initial assessment**: An ethical hacker can understand a network's sophistication by noting if and how it performs DPI. A network with robust DPI might indicate a more mature security posture, prompting the ethical hacker to consider more advanced evasion techniques.
- **Test basic evasion techniques**: Ethical hackers can experiment with simple obfuscation or port changes to see if a basic DPI system can detect and classify traffic, which helps in understanding the baseline detection capabilities of the target's security controls.

Here's how APA can be used in ethical hacking:

- **Developing advanced evasion strategies**: APA is designed to catch polymorphic malware, zero-day attacks, and complex data exfiltration. Ethical hackers need to understand these APA techniques (e.g., behavioral analysis, sandboxing) to craft payloads and communication methods that can realistically mimic advanced threats. It involves learning to mimic cryptography, use cryptography, and evade sandbox detection.
- **Identifying blind spots in advanced defenses**: By understanding how APA systems reconstruct sessions, de-obfuscate code, and perform dynamic analysis, ethical hackers can look for areas where these advanced defenses might be vulnerable.
- **Validating threat intelligence integration**: Ethical hackers can test if a target's APA system effectively integrates and acts upon current threat intelligence using indicators associated with recent, publicly known vulnerabilities or malware campaigns.
- **Optimizing exploit delivery**: Knowledge of APA helps ethical hackers fine-tune their exploit delivery methods. If an APA system is likely to detonate suspicious files in a sandbox, the ethical hacker can test how long their payload can remain dormant before activating to bypass sandbox detection.
- **Reconnaissance of application behavior**: APA's deep understanding of application protocols allows ethical hackers to gain profound insights into how target applications communicate, potentially finding vulnerabilities or unusual dependencies that could be exploited.


### Wireshark packet analysis

- **Frame**: General information about the capture itself.
- **Ethernet II (or IEEE 802.11 for Wi-Fi)**: The lowest network layer, showing MAC addresses.
- **Internet Protocol Version 4 (or IPv4)**: The IP layer, showing IP addresses, TTL, etc.
- **Transmission Control Protocol (or TCP) (or User Datagram Protocol (or UDP))**: The transport layer, showing port numbers and connection details.
- **Hypertext Transfer Protocol (or HTTP) (or Domain Name System (or DNS), etc.)**: The application layer is where the actual application data often resides for unencrypted traffic.

# Common Wireshark Protocols

## Common Wireshark protocols

Networks communicate using established rules and formats called protocols, such as shared languages, to ensure that devices understand each other. Wireshark is a powerful translator that dissects raw network data into understandable components based on these protocol rules. This guide highlights common network protocols and what Wireshark can reveal about them.

### TCP/IP suite

The TCP/IP suite is the foundational set of protocols that power the internet and most modern networks. It works in layers, each handling a specific part of communication.

|Protocol|What it does|What Wireshark displays|
|---|---|---|
|Internet Protocol (IP)|IP is responsible for addressing and routing data packets across different networks. It defines how each packet is addressed to find its way from a source to a destination device, often crossing many routers.|- **Source and destination IP addresses:** The unique numerical identifiers for the sending and receiving devices.<br><br>- **Protocol carried inside the IP packet:** Identifying the following layer protocol (TCP or UDP).<br><br>- **Time to live (TTL):** A counter that prevents packets from looping endlessly if they can't find their destination.|
|Transmission Control Protocol (TCP)|On top of IP, TCP provides reliable, ordered, and error-checked data delivery. It's like a guaranteed mail service: it ensures that data arrives correctly, completely, and in the proper sequence. TCP establishes a connection, manages the data flow, and retransmits lost pieces.|- **TCP's three-way handshake:** The initial conversation (SYN, SYN-ACK, ACK) to set up a reliable connection.<br><br>- **Sequence and acknowledgment numbers:** Used to order data segments and confirm receipt for reliability.<br><br>- **Source and destination port numbers:** Identifying the specific applications or services communicating.<br><br>- **TCP flags:** Indicators such as SYN, ACK, FIN, and RST show connection setup, acknowledgment, termination, or reset status.<br><br>- **Reassembled streams:** Wireshark can reassemble fragmented data from multiple TCP packets to show you the complete stream of reliably transferred data.|
|User Data Protocol|Sitting on top of IP, UDP offers a faster, connectionless way to send data. It's like sending a postcard – no guarantee of delivery or order, but it's quick, making it suitable for applications where speed is more critical than absolute reliability (i.e., live video streaming, online gaming, voice calls).|- **Source and destination port numbers:** Identifying the applications using UDP.<br><br>- **Length of the UDP data:** The payload size within the UDP segment.|

### Application protocols

Application protocols are specific to the applications people use every day. They define how software programs communicate to provide services.

|Protocol|What it does|What wireshark displays|
|---|---|---|
|Hypertext Transfer Protocol (HTTP)|HTTP is the fundamental protocol for communication on the World Wide Web. It defines how web browsers request web pages from servers and how servers send those pages back.|- **HTTP requests** (i.e., GET /index.html to request a webpage, POST for submitting data).<br><br>- **HTTP responses** (i.e., status codes such as 200 OK or 404 Not Found, and the content such as HTML).|
|Hypertext Transfer Protocol Secure (HTTPS)|The secure version of HTTP adds encryption to protect the data.|- Initial connection setup details<br><br>- Server's security certificate|
|Domain Name System (DNS)|DNS acts like the internet's phonebook. It translates human-readable website names into numerical IP addresses that computers understand.|- **DNS queries:** Requests for an IP address corresponding to a domain name.<br><br>- **DNS responses:** The IP address was returned for a queried domain name.|
|File Transfer Protocol (FTP)|FTP is a standard protocol to transfer files between a client and a server across a network.|- **FTP commands** (i.e., GET file.txt to download, PUT report.doc to upload, LIST to view directories).<br><br>- **FTP responses** from the server.<br><br>- **Actual file** data if it has been transferred without encryption.|

### Email protocols

These protocols govern the sending and receiving of email messages.

|Protocol|What it does|What Wireshark displays|
|---|---|---|
|Simple Mail Transfer Protocol (SNTP)|Handles sending outgoing email from your client to a mail server.|- Email headers (i.e., sender, recipient, subject, timestamps)<br><br>- The message body (for unencrypted mail)|
|Post Office Protocol version 3 (POP3)|Used for retrieving emails from a mail server, typically downloading them to your device and often deleting them from the server.|- Email headers (i.e., sender, recipient, subject, timestamps)<br><br>- The message body (for unencrypted mail)|
|Internet Message Access Protocol (IMAP)|Allows you to access and manage your emails directly on the mail server, synchronizing them across multiple devices.|- Email headers (i.e., sender, recipient, subject, timestamps)<br><br>- The message body (for unencrypted mail)|

### Routing protocols

These protocols are needed for data packets to travel efficiently from one network to another. They allow routers to share information about available network paths and choose the most efficient route.

|Protocol|What it does|What Wireshark displays|
|---|---|---|
|Open Shortest Path First (OSPF)|OSPF is a common Interior Gateway Protocol (IGP) routers used to find the best paths within a large organization's single, connected network (often called an Autonomous System). It ensures all that routers in the network know the fastest way to reach each other's connected networks.|- **Routing updates** between routers.<br><br>- **Link-state advertisements (LSAs)** – information about network links and their status.<br><br>- **Neighbor relationships** between routers.|
|Border Gateway Protocol (BGP)|BGP is the Primary Exterior Gateway Protocol (EGP) that governs how major internet service providers (ISPs) and large organizations exchange routing information across the global internet. It's how different parts of the internet "know" how to send traffic to each other.|- **BGP messages** including route advertisements (announcing reachable networks).<br><br>- **Route withdrawals** (removing previously advertised routes).<br><br>- **Route updates** (changes to existing routes).|

### Network management and monitoring protocols

Networks rely on these protocols to manage devices, collect performance data, and ensure smooth operations. Wireshark is useful for troubleshooting and auditing these management communications.

|Protocol|What it does|What Wireshark displays|
|---|---|---|
|Simple Network Management Protocol (SNMP)|SNMP is used to manage and monitor a vast array of network devices. It allows administrators to query device status, apply configuration changes, and receive automated alerts (called "traps") when significant events occur.|- **Community strings:** Simple passwords or access keys used for authentication in older SNMP versions (can be a security vulnerability if transmitted in plain text).<br><br>- **Object identifiers (OIDs):** Unique numerical codes identifying specific device parameters being queried or reported (i.e., CPU utilization, interface statistics).<br><br>- **SNMP traps:** Alert messages sent by devices to a central management station (i.e., device reboot, a network link going down).<br><br>- **Get/set requests:** Commands sent by administrators to retrieve information or modify device configurations.|
|Syslog protocol|Syslog is a standard protocol network device and server that sends system event messages (logs) to a centralized logging server. These logs are vital for monitoring, troubleshooting, and security auditing, providing a chronological record of events.|- **Facility and severity levels:** Indicating the type of system component (i.e., mail system, security daemon) and the message's criticality (i.e., emergency, error, informational).<br><br>- **Timestamp and hostname:** When and from where the event occurred.<br><br>- **Raw message content:** The actual textual description of the event (i.e., "Login failed for user 'admin,'" "Interface Gi0/1 changed state to up").|

# Summary

In this reading, you learned that:

- The TCP/IP suite is layered – It organizes network communication into layers, with each protocol handling a specific function, from routing (IP) to reliable transmission (TCP) to application-level services (HTTP, DNS, etc.).
- Wireshark reveals protocol details – Wireshark translates raw network traffic into readable data, such as IP addresses, port numbers, and protocol flags, making it an essential tool for network troubleshooting and analysis.
- TCP vs. UDP – TCP ensures reliable, ordered delivery through handshakes and acknowledgments, while UDP is faster but connectionless, best suited for real-time applications such as streaming and gaming.
- Application protocols are service-specific – Protocols such as HTTP, HTTPS, DNS, and FTP define how specific internet services work. Wireshark can show HTTP requests, DNS lookups, and even email headers.
- Network management and routing are critical – Protocols such as SNMP, Syslog, OSPF, and BGP enable administrators to manage devices, log system events, and ensure efficient data routing across networks.

|Ethical hacking task|What it means|How it's applied|

### Summary

In this reading, you learned that:

- Protocol analysis enables stealthy reconnaissance. Ethical hackers can gather valuable intel (e.g., IP addresses, hostnames, services) by passively monitoring ARP, DNS, and DHCP traffic, without alerting the target.
- Vulnerabilities are embedded in protocols: Poorly configured or outdated protocols (e.g., FTP, Telnet, SMB) often expose credentials or system weaknesses ripe for exploitation.
- Fingerprinting services reveals attack surface: By dissecting protocol headers (e.g., HTTP, DNS), hackers can determine running services and versions, helping tailor precise attacks.
- Security controls can be bypassed through obfuscation: Skilled attackers mimic benign protocol behavior or fragment traffic to slip past firewalls and DPI systems.
